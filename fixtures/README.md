# Fixtures

Test corpus for `magi`. Everything here is self-created or generated by the
scripts in `corpus/` — no third-party content, no licence obligations
(SPEC.md §8).

`corpus/` is what `magi-cli eval --corpus fixtures/corpus` and the golden
tests index. `golden/` holds expected extractor output. `reference_embeddings/`
holds vectors produced by `tools/reference_embeddings.py`.

from*; M4 Slice 2's `rxing` test asserts them byte-for-byte and is the point
at which they become verified. Never re-derive a payload by running the
decoder over the image and writing down whatever comes out.

- `corpus/qr/qr_text_es.png` → `código QR de prueba`

  (a photo of a QR code printed by a third party; recorded by the repo owner)

OCR ground truth for the image fixtures is in `golden/ocr/fixture_stem.txt`,
one `## <fixture stem>` section per image.

## Metadata is stripped before committing

Camera photos arrive carrying GPS coordinates, device make/model, firmware
build strings, capture timestamps, and — on Samsung — a proprietary `sefd`
trailer holding the network's mobile country code and an on-device file path.
None of that belongs in a public repo.

`scrub_metadata.py` removes it without re-encoding a single pixel:

```sh
python fixtures/scrub_metadata.py fixtures/corpus/images/new_photo.jpg
python fixtures/scrub_metadata.py --check fixtures/corpus/images/*   # before committing
```

JPEG metadata segments are dropped from the marker stream, and the file is
truncated at the primary image's EOI — a phone JPEG appends a *second*
complete JPEG (MPF) after it, with its own EXIF and XMP. HEIF metadata item
payloads are overwritten in place with a valid empty replacement of the same
length, so every `iloc` offset stays correct, and the trailing `sefd` box is
truncated.

Nothing is lost that any test needs: **HEIC orientation lives in the
container's `irot` transform, not in EXIF** (verified — `heic_rs::probe`
reports `Ccw270` for the portrait fixtures, whose EXIF is now empty), and no
committed JPEG had a non-trivial EXIF `Orientation`. Verified after
scrubbing: identical dimensions, identical container rotation, and
byte-identical decoded pixels from both `heic-rs` and `libheif-rs` on every
HEIC, and identical decoded pixels on every JPEG.

`--check` reports identifying strings rather than metadata structure, so a
scrubbed file's empty EXIF block does not trip it, and `edge/rotated_exif.jpg`
is allowed to keep the one EXIF tag it exists to carry. It only looks at
binary fixture formats; a `.txt` fixture or this README would false-positive
on the very words it searches for.

## Local-only fixtures (not committed)

These are listed in the repo's `.gitignore`. Tests and benchmarks that need
them **skip with a warning when they are absent**, so a fresh clone and CI
stay green — the affected numbers are then only measurable on a machine that
has them.

| File | Why not committed | What CI loses |
| --- | --- | --- |
| `corpus/images/receipt_es.jpg` | Photo of a real receipt: full name, national ID number, phone, email and address. | One extra (hard) OCR CER sample. SPEC §7 M4 only requires CER on the English and Spanish *screenshot* fixtures, which are committed. |
| `corpus/images/iphone_12mp_portrait.heic`, `iphone_12mp_landscape.heic` | Photograph a gift card addressed to the repo owner by name. | Nothing: `iphone_text_es.heic` (3000 × 4000) and `shelf_christmas.heic` (4000 × 3000) are both 12 MP iPhone HEICs in the two orientations, so the HEIC decode and orientation goldens still have committed fixtures. |
| `golden/ocr/personal.md` | The transcribed ground truth for all of the above. | — |
| `corpus/images/mustang_landscape.arw` | 49 MB Sony RAW. RAW is not a supported file kind (`discovery::classify` has no `arw`), so it is out of scope for v1. | Nothing. `mustang_landscape.jpg` is the same shot and is committed. |
| `corpus/images/NOT_A_HEIC_mustang_20mp.ppm` | 121 MB, and mislabelled: it is a Netpbm P6 export (5492×3672, 16-bit), not a HEIC. | Nothing — it was never a valid fixture. |

**If one of these ever has to be committed:** redact rather than reach for
Git LFS. Crop the customer block out of the receipt and rewrite its ground
truth, or photograph a receipt printed from a synthetic order. LFS costs
every CI checkout bandwidth against a 1 GB/month free quota, and it does not
make the personal data any less published.

## Missing

- **A decision on `corpus/edge/huge_real.pdf`.** The metadata gate found a
  real third party's name in `/Author`, `dc:creator` and the XMP packet, plus
  a document UUID and an embedded image's EXIF. It is also a Microsoft
  PowerPoint export, so it is third-party content, which SPEC.md §8 says the
  fixtures are not. It has been committed since M2, so dropping it from HEAD
  does not remove it from history. Replacing it with a generated equivalent
  from `corpus/generate_pdfs.py` is cheap and fixes both problems going
  forward; whether the history is worth rewriting is a human call.
- **Real iPhone fixtures.** SPEC.md §7 M4 asks for self-shot *iPhone* HEICs.
  The ones here were shot on a Samsung Galaxy S24 FE; the filenames were
  kept so a real iPhone shot can replace a file in place. Structurally they
  are close (tile grid, HEVC, an aux HDR gain map), but they are not the
  same thing: Apple's Live Photo `.MOV` sibling and its 10-bit variants are
  untested. Either supply iPhone shots or amend SPEC.md §7 M4 to say
  "phone-camera HEIC".
- **`corpus/images/iphone_48mp_landscape.heic`** — SPEC §7 M4 requires a real
  48 MP iPhone HEIC for the "< 3 s, RSS Δ < 400 MB" budget. The file that
  previously carried this name was a PPM export, not a HEIC (see above).
  Needs an iPhone 14 Pro or later with Settings → Camera → Formats →
  Resolution Control on, shooting at 48 MP HEIC Max.
